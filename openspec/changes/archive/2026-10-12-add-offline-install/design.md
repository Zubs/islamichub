# Design

## Context

`public/service-worker.js` is feature 4's self-removing worker. No manifest is published. Fonts come from Google Fonts. The hadith library calls hadithapi.com directly until feature 13.

## Decisions

- **`vite-plugin-pwa` in `generateSW` mode, `filename: 'service-worker.js'`, `registerType: 'prompt'`.** The plugin precaches every built file, which is what "every route opens offline" needs, and `navigateFallback` serves `index.html` for any route.
- **Old-app clean-up moves into `public/sw-legacy.js`, loaded with `importScripts`.** If the `islamichub-shell-v2` cache exists it skips waiting, deletes that cache and reloads open windows, which is feature 4's behaviour; otherwise it does nothing. It never unregisters, since this worker is meant to stay. Feature 4's tests are rewritten against it.
- **Fonts: runtime `CacheFirst` for the two Google Fonts hosts, plus a warm-up.** The first page load happens before the worker controls the page, so its fonts would not be stored. Once the worker is ready, `usePwa` re-requests the font addresses the page has already loaded (read from the browser's resource timings), which the worker then stores from the browser's own cache at no real cost. Alternative: self-hosting the fonts; a bigger change with new files to maintain.
- **Hadith requests: runtime `NetworkFirst` with a three-second network limit**, matching both hadithapi.com now and `/api/hadith/` after feature 13. The hadith views show an offline message when a request fails and `navigator.onLine` is false.
- **Zakat prices are kept in `localStorage` under `zakat-prices`** (`{ usdPerOunce, rates, date }`) rather than in the worker's cache, so the store can say where its prices came from and tests can cover it. Read through a pure `parseSavedPrices`. The status line gains a "saved" state with the age in days.
- **`usePwa.js`** holds the three pieces of state the interface needs (`needRefresh`, `canInstall`, `showIosNote`) and wraps `virtual:pwa-register`. Tests alias the virtual module to a stub.
- **`AppInstall.vue`** in `App.vue` renders the update notice, the Install button and the iPhone note as one small bar.
- **Icons are generated by a script** (`scripts/make-icons.py`, standard library only) from the favicon's geometry and committed as PNGs.
- **Size limit: `test/build.test.js` builds the site into a temporary folder** and sums the home page's document, the scripts and styles it links or preloads. It also checks the manifest's icons exist, the worker file exists and every route's chunk is in the precache list.

## Risks / Trade-offs

- [A broken worker can strand visitors, as the old app's did] → `registerType: 'prompt'` with `cleanupOutdatedCaches`, the worker file is never cached by the browser, and the legacy clean-up stays.
- [Real installation and flight-mode behaviour cannot be tested here] → listed under "Final" as Zubair's checks; the feature stays unticked.
- [The hadith API key is part of cached request addresses] → already true of the browser's HTTP cache; feature 13 removes the key from the client.
